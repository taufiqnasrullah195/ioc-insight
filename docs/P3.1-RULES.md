# P3.1 — Detection Rules Engine

**Tujuan:** keputusan verdict/aşık datang dari ATURAN MILIK ANALYST (bukan AI/kotak hitam).
Aturan ditulis di `rules.yaml`, dievaluasi terhadap setiap hasil enrichment,
menghasilkan verdict + action deterministik. AI hanya menjelaskan — tidak memutuskan.

## Format aturan (rules.yaml)

```yaml
- name: high-confidence-phishing-domain
  description: Domain muda + sinyal jahat dari sumber lain
  when:
    ioc_type: domain            # ipv4|ipv6|domain|url|md5|sha1|sha256
  conditions:
    - field: whois_age.age_days
      op: lt
      value: 30
    - any:                       # minimal satu terpenuhi
        - field: urlscan.malicious_votes
          op: gte
          value: 1
        - field: otx.malicious_votes
          op: gte
          value: 1
  verdict: MALICIOUS
  action: BLOCK
  confidence: 90

- name: noisy-scanner-benign
  when: { ioc_type: ipv4 }
  conditions:
    - field: greynoise.tags
      op: contains
      value: known-benign-service
  verdict: CLEAN
  action: LIKELY_FALSE_POSITIVE
  confidence: 85
```

## Semantik evaluasi

- `when.ioc_type` — aturan hanya berlaku untuk tipe itu
- `conditions` — list; default AND. `any:` = OR untuk sub-list
- `field` — `<source>.<atribut>` dari AnalyzerResult; atribut yang dikenal:
  - `malicious_votes`, `reputation_score`, `tags`
  - `whois_age.age_days` (dari raw.age_days)
- `op` — `eq, ne, lt, lte, gt, gte, contains, exists, not_exists`
- Aturan dievaluasi berurutan; **aturan pertama yang cocok menang**
- Tidak ada yang cocok → jatuh ke heuristic score band (fallback)

## Output

`LookupResult.rule_match` berisi nama aturan yang memicu → muncul di
report, timeline, dan notifikasi. Ini bukti audit untuk "kenapa diblokir".
